# NativeSX2 / Underdog GS Rendering V02: D3D11 sprite parity

**Status:** Verified, limited real GPU rasterization on Host 02, November 11, 2026.  
**Engineering scope:** External NativeSX2 research candidate, opt-in source-separated fixture. No game executables, ISO files or proprietary assets. No changes to Underdog `main` or AIOS Drive scope registry.

## Result

A genuine PS2Recomp `GSCpuBackend` (upstream GPL-3.0, pinned revision `e5636981a1c9de368f6b71e819c3dc188dfedbf4`) was compiled in an isolated Host 02 evaluation directory. It renders a single textured GS sprite into a 64×64 PSMCT32 framebuffer.

The separate self-contained MIT-compatible D3D11 fixture in `tests/gs_sprite_d3d11_v02.cpp` renders the **same single synthetic sprite** with VS 5.0 / PS 5.0 shaders into an offscreen R8G8B8A8_UINT target. It reads the texture input and CPU oracle image from local external test files. The GPU shader is **not** yet a runtime `GSRasterBackend` subclass and does not accept arbitrary GS batches.

The CPU sequence consists of:
1. `GSCpuBackend::Initialize` with 4 MiB GS VRAM.
2. `BeginTransfer` + `UploadImage` for an 8×8 PSMCT32 texture at TBP 128, with 64 texels checked through `ReadVram`.
3. `TextureFlush`, then `Submit(GS_PRIM_SPRITE)` for a 32×32 sprite positioned at (8,8)-(40,40), using FST texture coordinates, CLAMP and DECAL with texture alpha.
4. `Flush`, `Sync(Presentation)`, and framebuffer `ReadVram` for 4096 pixels.
5. `Present` with a 64×64 CRT1 configuration. RGB channels were independently compared with the GS VRAM image and matched; the presentation alpha normalization semantics were deliberately excluded from the raw VRAM comparison.

A controlled **negative test** flipped one red channel in one source texel. The validator detected **16 changed output pixels** and returned a failing exit code. Restoring the input returned PASS. This protects the test from trivial success checks and confirms a changed source input affects the GPU image. The CPU output, Intel readback, and WARP readback binary SHA-256 digests matched exactly on the primary fixture.

## Boundaries and next gate

**This does not establish:** NativeSX2 or God of War boot; a replacement GPU driver; HD 4000 execution; a plug-in GPU backend to PS2Recomp; shader speedups; equivalence for triangles, blends, depth, texture aliasing, indexed PSM, framebuffer feedback, or all GS presents.

**Next engineering gate:** Parameterize the sprite from `GSPrimitiveBatch`, add a source-separated opt-in D3D11 `GSRasterBackend` implementation with CPU fallback for unhandled operations, and validate stateful texture uploads, flush/sync, VRAM snapshots, feedback and `PresentationFrame`. Only then consider real-game integration. D3D11 avoids requiring D3D12 but HD 4000 remains a separately necessary hardware validation.

## Reproducing the opt-in hardware test without GPL source files

The checked-in `tools/generate_gs_sprite_fixture_v02.py` independently generates the *same* synthetic texture and target framebuffer. Its output was checked byte-for-byte against the authentic `GSCpuBackend` oracle on Host 02 and reproduced the Intel/WARP GPU results in a separate staging folder. This independent generator is a **reproduction convenience**, not a replacement for the upstream CPU oracle as the final correctness authority.

From the repository root on Windows:

```powershell
python tools/generate_gs_sprite_fixture_v02.py --output C:\temp\underdog-gs-fixture-v02
cmake -S . -B build -G "Visual Studio 17 2022" -A x64 -DBUILD_TESTING=ON
cmake --build build --config Release --target underdog_gs_sprite_d3d11
Push-Location C:\temp\underdog-gs-fixture-v02
& '<repo>\build\Release\underdog_gs_sprite_d3d11.exe'
& '<repo>\build\Release\underdog_gs_sprite_d3d11.exe' warp
Pop-Location
```

Replace `<repo>` with the actual repository path. The executable expects the two fixture files in the current working directory. `ctest --test-dir build -C Release --output-on-failure` separately validates the generator's pinned checksums without executing GPU code. Do not confuse passing this source/generator check with a hardware graphics verification.
